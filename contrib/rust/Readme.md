# Растовые контрибы

Пока завозятся руками. Тул импорта — отдельная задача, здесь описано то, чего
он должен придерживаться, и то, что уже зафиксировано в конфиге.

## Раскладка

Один крейт — один каталог, имя каталога совпадает с именем на crates.io
(с дефисами, как там). Внутри — распакованный crate-файл и рукописный `ya.make`:

```text
RUST_CRATE(serde_json)

RUST_EDITION(2021)
VERSION(1.0.140)
LICENSE(MIT OR Apache-2.0)

PEERDIR(
    contrib/rust/serde
)

END()
```

Имя модуля — аргумент `RUST_CRATE()` — обязательно всегда, когда имя каталога
не является корректным идентификатором раста, то есть почти всегда. Оно задаёт
и имя крейта, и имя артефакта (`libserde_json.rlib`), и расходиться они не
могут: прямые потребители получают крейт через `--extern`, а транзитивные
rustc разрешает через `-L` по имени файла, никогда по метаданным. По умолчанию
берётся имя каталога, поэтому у `anyhow` аргумента нет.

Две версии одного крейта живут в разных каталогах (`syn-1`, `syn-2`) с
одинаковым `RUST_CRATE(syn)`, и каждый потребитель делает `PEERDIR` на нужную.

`RUST_EDITION` берётся из `edition` в `Cargo.toml` крейта; по умолчанию 2024.

## Версия тулчейна

Один rustc на весь репозиторий, задаётся в `build/platform/rust`. `MSRV`
крейтов проверяется при завозе, а не в сборке.

`rust-toolchain.toml` из архивов крейтов вычищается: он относится к сборке
крейта через cargo и в аркадийной сборке не участвует, но сбивает с толку.

## Известные дыры

**`build.rs` не исполняется.** У `anyhow` он молча игнорируется — там пробинг
фич компилятора, и без него крейт собирается. В общем случае замена — прописать
нужные `--cfg` через `RUST_FLAGS()` при завозе (например,
`RUST_FLAGS(--cfg wrap_proc_macro)` у `proc-macro2`), а файлы, которые скрипт
генерирует в `OUT_DIR`, — закоммитить рядом с исходниками и перенацелить
`include!`. Значения, которые крейт читает через `env!()` (`CARGO_PKG_*`),
задаются `RUST_ENV(Var=Value)`.

**Cargo features.** Один фиксированный набор на репозиторий, выбирается при
завозе и включается через `RUST_FLAGS(--cfg feature=\\"имя\\")` — кавычки
обязательны для rustc, и парсер `ya.make` снимает один уровень экранирования,
отсюда `\\"`. Опциональная зависимость — тоже фича (неявная, с именем
зависимости), и гейтиться код может именно на неё. Коллизия «двум потребителям
нужны несовместимые наборы» осознанно отложена.

**Target-specific зависимости** (`[target.'cfg(unix)'.dependencies]`) — тоже
не решены: либо условные `PEERDIR` через `when`, либо завоз объединения.

**`tests/`, `benches/`, `examples/`** из архива крейта сейчас лежат мёртвым
грузом (см. `anyhow/tests`). Вычищать их или нет — не решено.
